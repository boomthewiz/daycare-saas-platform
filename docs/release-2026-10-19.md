## Delivered scope

P1 separates immutable ordinary activity intent from clinical preparation/execution/notes and adds a configuration-only attendance activation checklist. See [P1 decisions and compatibility](p1-activity-attendance-activation.md).

The eight P2 items are addressed in the original order:

1. Saved-choice search/pagination runs on the server by kind/query. Selected/recent/new IDs resolve independently, including the reproduced case of 530 earlier tags hiding a new location. Legacy `session_context` retains its historical response; new clients use `session_context_v2` and paginated search.
2. Attendance export retains the visible visits while freshly authorizing the export page. Lock/auth/filter cancellation remains authoritative.
3. Interrupted session saves persist only an opaque operation UUID under an actor/org-scoped browser key, never child/session details or a payload fingerprint. Reload recovery checks a current-authority server receipt. Canceling an unconfirmed attempt writes a server tombstone under the same organization lock used by creation; delayed old/new requests cannot later commit that canceled operation. A committed operation is recovered rather than canceled or duplicated. Same-tab unchanged retries preserve their operation ID. This is not offline scheduling or indefinite recovery of unsaved form drafts.
4. Session managers explicitly rename/archive/restore choices with version conflict checks and duplicate review. Existing uniqueness is retained across active and archived names: archive/recreate never silently creates a second identity; restore is explicit. Domains and historical tag snapshots are unchanged. Location choices remain distinct from recorded/custom scheduling text; archiving a reusable location does not rewrite or ban historical text. Favorites and pinned presets remain later work.
5. Corrections accept organization-local civil times using the visit's recorded timezone. Server candidates reject DST gaps and expose both UTC occurrences for repeated times; staff explicitly choose an occurrence. The server validates the civil-time/instant pair, then applies the existing seven-local-date, branch/grant/version/subscription/history rules. Original UTC callers remain compatible.
6. A committed schema-only fixture, pinned test dependencies, required preflight and GitHub Actions check remove external baseline/runtime requirements and skip-based false success. Native concurrency remains a required CI component. See [testing instructions](testing.md).
7. Current release documentation and registry status are refreshed. Older implementation notes remain dated history with links to this record. Actual remote migration versions and production deployment identity are recorded below.
8. Tasks uses assigned-user or existing child/session-manager authority, organization-local due-date boundaries, current client links and visible error/retry states. Legacy child/classroom references are retained and clearly labeled; no mapping is guessed. Date-only legacy tasks use their recorded date with an explicit unknown-original-timezone label. Managers can see organization tasks and explicitly assign/reassign them to active organization accounts, with stale-assignment checks; staff see their own assignments. Read-only production checks found the existing legacy tasks unassigned. They remain intact and manager-visible; the release makes no automatic assignments. Completion updates check stale state and current authority. This does not repair or certify legacy automatic task generation, create classroom enrollment or establish D5 care completeness.
